# AGENTS.md — python-rasenmaeher-scep

## Purpose

A SCEP responder, so an MDM can enrol Android devices into a RASENMAEHER deployment with no
application of ours on the phone. The device generates its own key, the MDM proxies the certificate
request here, and this service asks RASENMAEHER to complete an enrolment an admin has already
planned. It is not a certificate authority and it must never become one.

## Stack

- Python 3.11+, FastAPI, uvicorn/gunicorn, httpx
- `cryptography` for keys and signatures, `asn1crypto` for the parts of CMS that `cryptography`
  cannot express (SCEP's custom signed attributes)
- `libpvarki` for ECS logging and the healthcheck schema
- uv, ruff, mypy strict, pytest, prek. The pre-commit config is generated from
  [config-ci-library](https://github.com/pvarki/config-ci-library) — never hand edit the
  autogenerated section.

## Running the tests

```bash
uv sync
uv run pytest
```

The protocol tests build certificate requests in memory and need no network, no MDM and no phone.

## The rules this service lives by

**It holds no authority.** Its only capability is one call to RASENMAEHER's
`POST /api/v1/enrollment/accept`, authenticated with its own client certificate from the deployment
CA. RASENMAEHER's `RM_MDM_AGENT_CNS` decides whether our CN may do that. We cannot create a
callsign, cannot approve anything a human started, cannot revoke and cannot sign. If you find
yourself wanting a broader credential, the design is wrong, not the credential.

**Never register this as a kraftwerk product.** A product CN in this platform may have *any*
certificate request signed regardless of its subject, skips role checks entirely, and is treated as
permanently valid by the edge. That is impersonation of anyone, handed to a service that parses
ASN.1 from the open internet.

**The RA key is RSA and that is not negotiable.** SCEP wraps the request in a CMS EnvelopedData
whose content encryption key is transported with the recipient's public key, which is an RSA
operation. `cryptography` refuses an elliptic curve recipient outright. Everything else we generate
is a curve; this one thing cannot be.

**The challenge is not a secret.** It sits in the MDM's configuration and travels in every device's
request. It keeps noise off the endpoint. The control is that an admin planned the callsign, and it
lives in RASENMAEHER, not here. Do not log it, and do not let it grow into a credential.

**Refuse, do not guess.** Every refusal is a signed CertRep carrying a failInfo, so the MDM reports
a failed certificate instead of retrying for ever. There is no PENDING state: every answer is final.

**One deployment per container.** No multi-deployment routing. A unit running several Deploy Apps
runs several of these, each with its own domain.

## Things that bit us on real hardware

- **BER, not DER.** SCEP clients built on BouncyCastle (jscep, and therefore the Fleet Android
  agent) send the envelope with indefinite length constructed encoding. `pkcs7_decrypt_der` is a
  strict DER parser and rejects it with `ParseError { kind: InvalidLength }`. We re-encode through
  asn1crypto first. `test_ber_encoded_envelope` pins it.
- **The signature covers the untagged attributes.** RFC 5652 §5.4: the signature is computed over
  the signed attributes encoded as an explicit SET OF, not the implicitly tagged `[0]` they appear
  as inside SignerInfo. Verifying the tagged form rejects every genuine request.
- **Generate the RA identity before the workers start.** `rmscep init-ra` in the entrypoint.
  Workers racing on an empty directory each generate a key and only one of them is the one devices
  encrypted to.
- **An empty common name is normal.** An MDM whose subject template has not been filled in yet
  sends one. Refuse it here so we never ask RASENMAEHER about a callsign nobody planned.
